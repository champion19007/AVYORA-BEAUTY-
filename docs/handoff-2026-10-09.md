# Avyora desktop build: handoff for owner review

9 October 2026 · branch `feat/customer-accounts` · prompts 22–30 are uncommitted on top of `7f5225d`

This is the desktop build for owner testing. **It is not deployed.** Production runs the last merged build (PR #14) with migrations 0000–0019. Mobile and tablet design have not started.

## 1. How to review it

The review build runs without any database (no stock, catalogue prices, nothing saved). That is the safe way to look at the design.

```bash
NEXT_PUBLIC_REDESIGN=1 NEXT_PUBLIC_FACE_SCAN=1 npm run build:offline
```

```bash
node scripts/dev-redesign.mjs --start 9004
```

Open http://localhost:9004 at a desktop width (1280, 1440 or 1920). The `.claude/launch.json` entry `start-redesign` does the same.

To see stock, saving, accounts, reviews and scans, run against a **local** database that has migrations 0020 and 0021 (`npm run db:migrate` with `.env.local` pointing at it). Never point it at production.

## 2. Feature flags

All are off by default, and every one is reversible by unsetting it. `NEXT_PUBLIC_*` flags are read at build time, so changing one needs a rebuild.

| Flag | Turns on | Also needs |
| --- | --- | --- |
| `NEXT_PUBLIC_REDESIGN=1` | Nuvē-style desktop shell, landing page and theme for every page | Nothing; unset gives the previous UI |
| `NEXT_PUBLIC_FACE_SCAN=1` | `/scan` and its entry in the routine finder; photos checked in the browser only | Nothing |
| `FACE_SCAN_HOSTED=1` | Private photo upload for signed-in accounts | `PRIVATE_STORAGE`, a database; analysis still unavailable (no model) |
| `PRIVATE_STORAGE=local` | Development-only private photo folder | Hosted storage is **not** built: leave unset in production |
| `PRIVATE_STORAGE_SIGNING_SECRET` | Short-lived private read tokens | Falls back to `AUTH_SECRET` |
| `NEXT_PUBLIC_NEWSLETTER=1` | Footer sign-up form | Migration 0021 |
| `NEWSLETTER_ENABLED=1` | The sign-up endpoint (double opt-in) | `RESEND_API_KEY`, `EMAIL_FROM` |

### 4.1 Tests

Full suite (77 files): **911 passed, 3 skipped**. Two files failed in that run, both at module import before any test ran: `order-status-flow.test.ts` and `scan-inference.integration.test.ts` ("Cannot find module /src/db/schema"). Both pass on their own (14/14). The previous full run had a different file (`jobs.integration.test.ts`) fail the same way, then pass alone (10/10). This points to import-time load at 4 workers, with PGlite migrations at import, rather than a code fault. It is worth reducing `maxWorkers` or moving migrations out of import time if it persists in CI.

## 6. Rollback

| Change | How to undo |
| --- | --- |
| Redesign or any new feature | Unset its flag and rebuild. The previous UI and behaviour return; no data is involved |
| This uncommitted work | Not committed; discard or keep with git as you choose. Production is unaffected |
| Migrations 0020 and 0021 | Not applied to production. If applied later, they only add tables. Undoing them (`DROP TABLE support_requests` / `newsletter_subscribers`) loses those rows, so do it only on purpose |
| Production data before 0014–0019 | Neon branch `backup-before-0014-0019-2026-10-08` (`br-snowy-lab-b31ngh16`) |
| A bad production deploy | Promote the previous deployment in Vercel |
